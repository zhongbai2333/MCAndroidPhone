共享底盘采用 QEMU 官方支持的 [backing file / overlay](https://www.qemu.org/docs/master/tools/qemu-img.html) 机制。该机制允许差分盘只保存修改内容，但已被设备引用的底盘必须保留且不可改写。它减少每台设备新增占用，不减少第一次下载的系统镜像大小。

普通 Android Camera2 接入是另一个功能缺口：此前真实测试中 AOSP `virtual_camera` 被 `GL_EXT_YUV_target not supported` 阻止。游戏相机 APK 预览/拍照成功不能替代 Camera2 验收。应独立研究兼容的图形后端或 CPU 相机 HAL，不能跳过能力检查冒充支持。

## 本次已完成：稳定打包与缓存标识

运行时缓存目录由完整清单的 SHA-256 决定。原 `Properties.store` 在清单中加入时间戳，即使内容没变，重新打包也可能生成另一个缓存目录；staging 配置同样带时间戳。

`BundleMetadata` 保留标准 properties 转义，移除生成时间并按行排序；`PackageRuntime` 固定 ZIP 日期和条目顺序，`StageMacRuntime` 使用相同的配置写入方式。清单 schema 和运行时完整性验证不变。

本机已通过 `java scripts/PackageRuntimeSelfTest.java`：跨时间、时区、输入文件时间和原始 ZIP 顺序产生逐字节相同的小型测试包；Unicode/换行配置往返一致；mod 更新保持运行时清单一致，镜像更新改变清单。该检查已加入三操作系统 CI 配置，远程 CI 尚未运行。

保证范围是同一打包工具/JDK 下相同输入内容的打包；不保证不同压缩器或原生工具链产物相同。没有重新生成 1.08 GiB 大包，也没有删除历史缓存或迁移已有设备。首次切换到新清单仍会产生一个新缓存目录，后续相同输入才会稳定复用。
